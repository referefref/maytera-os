Panel geometry (the port contract)

PANEL_W = 296. Panel origin x0 = w - 296, spanning y in [0, h]. Content inset 12 px each side, so content x starts at x0 + 12, content width 272. Left edge is a 1 px --accent line. Section band/header text sizes: title 14, header 11, rows/buttons 12. Row pitch ~18 px; section gap = divider (1 px) + 8 px. Buttons are 24 px tall with a 1 px top-highlight / bottom-shadow bevel (same bevel as the existing barbtn()). Dpad buttons 54 px wide, 26 px tall, 5 px gap, laid N-top / W-Stop-E / S-bottom.

Capability gating

On connect the app also GETs /canslew, /cansync, /canpark, /canunpark, /canfindhome, /cansettracking, /canmoveaxis?Axis=0. A button whose capability is false renders .dis (disabled tokens) and its key is a no-op with a status note, rather than sending a command the mount will reject.

Async contract

Every command goes through the existing single-in-flight alpaca_step() state machine, extended with a small bounded op QUEUE so multiple key presses serialise WITHOUT blocking. The render thread never blocks on the network: at most one non-blocking syscall's progress per frame, exactly as the RA/Dec poll already does ([[no-block-context-cannot-wait-event-async-tx]]). A slow or absent endpoint cannot freeze the sky.
