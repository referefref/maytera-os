# ClassiCube offline resource preload (#28, 2026-08-17)

## What this is

`default.zip` and `classicube.zip` in this directory are shipped on the ext2
root partition at `/GAMES/CLASSICUBE/texpacks/` (see `build/build-golden.sh`)
so ClassiCube reaches its menu and a rendered singleplayer world with **zero
network access**, on the owner's real iMac14,4 which has no working NIC.

They are generated by `gen-default-texpack.py`, not hand-crafted, so they can
be reproduced or regenerated exactly:

```
python3 gen-default-texpack.py <outdir> <path-to-maytera-src-checkout>
```

## Why this exists instead of the real Minecraft textures

Upstream ClassiCube has no bundled default texture pack of its own. On first
run it downloads Mojang's official "classic jar" / "1.6.2 jar" client
archives over HTTP and patches textures out of them
(`vendor/ClassiCube/src/Resources.c`). Those textures are Mojang/Microsoft
copyrighted. MayteraOS has no licence to redistribute them inside the OS
image, so this script does not touch, download, or derive anything from a
Mojang asset, ever. See `ATTRIBUTION.md` at the repository root for the full
reasoning and the exact provenance of every file this generates.

## What is in each file

`default.zip` contains every entry `vendor/ClassiCube/src/Resources.c`'s
`defaultZipEntries[]` requires for `Resources_CheckExistence()`'s
`allZipEntriesExist` check to pass (which is what stops the launcher from
ever calling `Http_AsyncGetData` for textures):

| File | Size | Content |
|---|---|---|
| `terrain.png` | 256x256 | 16x16 tile grid, themed flat colours for common blocks (grass/dirt/stone/sand/water/wool bank/...), HSV-wheel colours for the rest |
| `particles.png` | 128x128 | 16x16 grid of small coloured dots |
| `clouds.png` | 256x256 | procedural soft blotches (translucent) |
| `rain.png` | 32x32 | simple diagonal streak, tileable |
| `snow.png` | 16x16 | flat near-white tile |
| `char.png` | 64x32 | two-tone skin-coloured checker pattern |
| `creeper.png`, `pig.png`, `sheep.png`, `sheep_fur.png`, `skeleton.png`, `spider.png`, `zombie.png`, `chicken.png` | 64x32 each | two-tone, mob-themed colour pairs |
| `icons.png` | 256x256 | simple white crosshair + a health/food icon row |
| `gui.png`, `gui_classic.png` | 256x256 | flat dark panel occupying the used top half |
| `animations.png` | 16x512 | 32 stacked 16px frames, an orange/red colour-cycle for the `animations.txt` fire entry |
| `default.png` | 128x128 | **re-rasterised from ClassiCube's own `SystemFonts.c` `font_bitmap[]` table** (BSD-3, already vendored), not new art |
| `animations.txt` | - | byte-identical to the `ANIMS_TXT` constant already in `vendor/ClassiCube/src/Resources.c` |

`classicube.zip` is an empty, valid zip. It exists only to satisfy
`Resources.c`'s separate `File_Exists("texpacks/classicube.zip")` check
(`CCTextures_CheckExistence`); its content is never read on a desktop build
(`CCTextures_SelectEntry` only looks for `touch.png`, a mobile-only asset this
port does not build).

## What is deliberately NOT here

Sound and music. Upstream's default sound/music assets come from the same
Mojang jar as the textures, and there is no BSD-3 in-tree fallback comparable
to `font_bitmap[]` to substitute with. `engine-patches/coreh-maytera.py`
defines `CC_BUILD_NOMUSIC` and `CC_BUILD_NOSOUNDS` for the MayteraOS platform
branch instead, so the resource fetcher never lists audio as missing and the
game is silent rather than shipping or faking Mojang audio. Revisit this if
an original, MayteraOS-authored sound set is ever produced.

## This is a placeholder look, not a claim of authenticity

Tile colours in `terrain.png` are NOT verified against ClassiCube's real
`Block.c` texture-location table beyond a small hand-picked set (grass,
dirt, stone, sand, water, lava, wood, leaves, ores, glass, brick, obsidian,
the 16 wool colours). Every other tile gets a deterministic but otherwise
arbitrary colour. The game is fully playable and every block is visually
distinct, but this does not look like real Minecraft, intentionally: it
cannot, without redistributing Mojang's art.

A user with a working network connection can still get ClassiCube to use the
real textures: delete or move `texpacks/default.zip` and
`texpacks/classicube.zip`, and ClassiCube's own unmodified resource-fetch
code (this change does not touch `Http_Maytera.c`, `Socket_Maytera.c`, or any
vendored `Resources.c`/`TexturePack.c` logic) takes over exactly as upstream
intended, subject to Mojang's own terms for that download.
