# Writer toolbar icon set

Twenty toolbar glyphs for the native office suite's Writer app: new, open,
save, undo, redo, bold, italic, underline, strikethrough, align-left,
align-center, align-right, align-justify, list-bullet, list-numbered,
insert-table, insert-image, indent-increase, indent-decrease, find.
Original MayteraOS artwork, licensed like the rest of the OS (GPLv2); nothing
here is third-party, so `ATTRIBUTION.md` needs no entry for it.

## What is here

| Path | Form |
|------|------|
| `*.svg` | The masters. `viewBox="0 0 24 24"`, white on transparent, `fill="none" stroke="#ffffff" stroke-width="1.5"` (round caps and joins), plus solid white fills for the bullet dots, the sun, and the list digits. |
| `icn/WR*.ICN` | The consumed raster: MICO (`'MICO'` + u32 LE w + u32 LE h + w*h little-endian 0xAARRGGBB), 64x64, one per icon, 16396 bytes each. |
| `MANIFEST.tsv` | The svg -> 8.3 name map. |
| `build-icn.sh`, `png2icn.py` | Regenerate `icn/` from the masters (rsvg-convert, then a stdlib-only PNG-to-MICO packer with a `--self-test`). |

## Why this format and size (the mechanism it matches)

Toolbar icons in the existing apps are not code-drawn and not PNG/BMP. Files
(`userland/apps/files/main.c`, `files_icon_btn` -> `draw_mico`) and Settings
(`userland/apps/settings/main.c`, `draw_mico`) each open `/ICONS/NAME.ICN`
(MICO, 64x64 max, the same format the compositor's `icon_load_color()` reads),
cache it, and draw it at the size the button wants: 16px in Files' command
bar, 13 to 22px in Settings. The draw is a nearest-neighbour sample
(`sx = dx*w/size`) and, when a tint is given, the glyph's luminance times
alpha becomes coverage recoloured to the theme ink, which is why every master
is a white glyph on transparency and why a coloured or badged icon would
break under a tint. All 117 shipped `/ICONS/*.ICN` are 64x64, so these are
too; `MICO_DIM` is 64 in Files and the loader rejects anything larger.

The masters are drawn on a 16-cell pixel grid, the size Files renders at:
the root `<g transform="translate(0.75 0.75) scale(1.5)">` maps cell `k` to
`0.75 + 1.5k`, so a 1-cell stroke is 1.5 viewBox units (the same 32/512
weight as the CoreUI set the app icons come from) and, after the 64x64
rasterization, every stroke is 4px wide and centred on a 4px sample column.
That is exactly one sample at 16px, so lines come out crisp instead of
flickering between one and two pixels. The numbered-list digits are 3x4
pixel-font cells for the same reason: stroke-drawn digits three to a 16px
column are a smudge. Safe area is cells 1..14 (14px of 16, the style guide's
16px rule).

Judge the set at the real size, through the real sampler, not at 1:1: the
scratch preview used for this set reproduces `draw_mico` (nearest sample,
luminance-as-coverage tint, light and dark toolbar surfaces) at 16, 20 and
24px. If you change a master, look at it that way before shipping.

## Names

The 8.3 names carry a `WR` prefix (`WRBOLD.ICN`, `WRALNL.ICN`, ...) because
`/ICONS` is one flat directory and a Calc or Slides toolbar will also want
new/open/save/undo/bold. See `MANIFEST.tsv` for the full map.

## Deploying

`.ICN` files are deliberately not regenerated by `build/build-golden.sh`; they
ship from the static asset base (`assets/icons/README.md`). To make these
reach a golden:

1. Copy `icn/WR*.ICN` into the asset base's ext2 root partition (p2) at
   `/ICONS/` (the partition that already holds the other 117 icons; the FAT
   ESP has none).
2. Append their sha256 rows to `build/asset-manifest.sha256` as
   `FREEWARE  /ICONS/WR*.ICN` so `build/repo-guard.sh`'s asset sample covers
   them.
3. In the app, draw with `draw_mico("WRBOLD", x, y, 16, ink)` or the shared
   equivalent; the loader falls back gracefully if a name is missing, so a
   typo shows as a blank button, not a crash. Check the name against
   `MANIFEST.tsv`.

## Regenerating

```
assets/office-icons/writer/build-icn.sh            # -> icn/WR*.ICN
python3 assets/office-icons/writer/png2icn.py --self-test
```
