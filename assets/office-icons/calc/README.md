# CALC (spreadsheet) toolbar icon set

Toolbar glyphs for the native office suite's spreadsheet app
(`userland/apps/sheets`, ships as `/APPS/SHEETS`, product name CALC).
Original MayteraOS artwork; no third-party icon library, no font glyphs.

## What is here

| dir | contents |
|---|---|
| `svg/` | 23 SVG masters, one per icon, `viewBox="0 0 24 24"` |
| `icn/` | the same 23 icons as 64x64 MICO `.ICN`, the format the toolbars actually load |
| `png/` | 64x64 RGBA reference rasters (what the `.ICN` was packed from) |
| `gen-icn.py` | regenerates `icn/` and `png/` from `svg/` (python3 + rsvg-convert, no PIL) |

## Mechanism matched

The Files and Settings toolbars do not draw SVG or PNG. Each app has a
self-contained MICO loader (`mico_get()` + `draw_mico()`,
`userland/apps/files/main.c`, mirrored in `userland/apps/settings/main.c`)
that opens `/ICONS/<NAME>.ICN`, reads `'MICO' + u32 LE w + u32 LE h + w*h`
BGRA pixels, nearest-neighbour scales the raster to the button's icon size
and, when a tint is given, uses the glyph's luminance times alpha as
coverage and recolours it to the theme ink. So a toolbar icon is a WHITE
glyph on transparent, with no background tile, and the app decides its
colour at draw time (dark ink on the light toolbar, light ink on the dark
one; the same file serves both themes).

Consequences that shaped this set:

- Authored on a 24-unit grid and rasterized ONCE straight to 64x64, the
  same source size as every other toolbar icon in `/ICONS/` (Writer `WR*`,
  Slides `OF*`/`SL*`). The office toolkit's loader (`officelib/officeui/
  oicon.c`) box-averages the 64px source to its 16px button glyph, so
  64->16 is an exact 4x4 average per pixel, which is what keeps a 1px-wide
  stroke at 16px from dropping rows. (The set was first cut at 24x24 for a
  nearest-neighbour 1:1 draw; that size never reached the asset base, and
  24->16 through the box filter gave 1- or 2-texel boxes and a visibly
  heavier line than the sibling sets, so it was re-rastered at 64.)
- White only, `fill="none"` strokes (plus a few solid white accents: the
  decimal point, the frozen corner cell). Coverage comes from luminance, so
  never use grey or coloured paint in these files.
- One grid, one weight: 2-unit safe margin (content within 3..21), stroke
  1.5 on the 24 grid = 4px at the 64px raster = 1px at 16px, which is the
  weight the Writer (1.5/24) and Slides (32/512) sets and the launcher icons
  (4/64) all use. Round caps and joins. Letter glyphs (B, I, U, $, %,
  sigma, fx, #) are stroked paths on that same grid so they weigh the same
  as the pictorial icons. `bold` is the one deliberate exception (stroke
  2): the heavier stroke is the meaning. The freeze-panes inner gridlines
  are 0.9 so the frozen edge reads heavier than the cell lattice. Measured
  at 16px through the loader's box filter: SCBOLD ink 49, SCNEW 53, SCSAVE
  65 against WRBOLD 58 / WRNEW 52 / WRSAVE 71 and OFBOLD 60 / OFNEW 53 (the
  old 24px SCBOLD was 76, the one that read too heavy).

## Deploying

`.ICN` files are NOT regenerated by `build/build-golden.sh`; icons live in
the static asset base image that the build overlays onto (see
`assets/icons/README.md`). DEPLOYED (officeintegrate, 2026-09-08): the 23
64x64 `icn/*.ICN` were copied to `/ICONS/` on the ext2 root (p2) of the
asset base `/ssdmirror/maytera-2part-ext2-b850.img` and their sha256 rows
added to `build/asset-manifest.sha256` (repo-guard fails the next golden
if the two disagree, so change both together). The committed copies under
`icn/` here are the reference; they are byte-for-byte what `gen-icn.py`
produces from `svg/`.

Using one from the app side is the toolkit call:
`oicon_draw(win, "SCBOLD", x, y, 16, ink, face)`.

## Regenerating

```
cd assets/office-icons/calc
python3 gen-icn.py            # 64x64 (default) -> icn/ and png/
```

`gen-icn.py` decodes rsvg-convert's PNG with the standard library, packs
the MICO header and BGRA order exactly as `mico_get()` reads it, and refuses
duplicate or over-long names.

## Sibling sets (SLIDES, WRITER)

`assets/office-icons/slides/` and `assets/office-icons/writer/` were drawn
in parallel by other agents and chose a 64x64 source with a 32-unit grid
(1.5px-equivalent butt/miter strokes, tuned for the Files 16px case) and
`OF*` names for the glyphs every office app shares (new, open, save, bold,
italic, align-*). This set originally differed from them in stroke (2.0
round vs their 1.5-equivalent) and source size (24 vs 64); both were
reconciled on 2026-09-08 (stroke 1.5, 64x64), so the three now match in
weight as well as motif. The shared six still exist in all three prefixes;
dropping the duplicates is a separate cleanup nothing here depends on.
